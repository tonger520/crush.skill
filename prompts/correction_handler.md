# 对话纠正处理器

## 触发条件

当用户表达以下内容时启动：
- "不对"/"TA不会这样"
- "TA应该是..."
- "TA其实是..."
- "这个不准"
- "TA不是这种性格"
- "其实TA..."

## 任务

用户对当前 crush Skill 的表现不满意，认为画像不准确。需要：
1. 识别用户在纠正什么
2. 判断属于 Profile 还是 Signals
3. 判断属于哪个 Layer/维度
4. 写入 Correction 层，立即生效
5. 重新生成 SKILL.md

---

## 纠正分类

### 类型 A：Profile 纠正

| 层级 | 纠正示例 | 处理方式 |
|------|---------|---------|
| **Layer 0 核心规则** | "TA不会忽冷忽热，TA其实一直很稳定" | 立即修改 Layer 0 规则 |
| **Layer 2 表达风格** | "TA不会说'呀'，TA说话很直男/直女" | 修改口头禅、语气描述 |
| **Layer 3 情绪逻辑** | "TA不会因为这样的话生气" | 修改情绪触发规则 |
| **Layer 4 关系行为** | "TA其实很讨厌别人问TA在干嘛" | 修改互动模式描述 |
| **Layer 5 边界雷区** | "TA不喜欢被叫宝贝" | 添加/修改边界 |

### 类型 B：Signal 纠正

| 维度 | 纠正示例 | 处理方式 |
|------|---------|---------|
| **主动性评分** | "TA其实经常主动找我" | 重新评估主动性评分 |
| **暧昧信号** | "TA对所有人都这样，不是特殊对待" | 降低暧昧信号评分，重新计算温度 |
| **温度评估** | "我们其实就是普通朋友" | 重新评估各维度，更新温度 |
| **趋势判断** | "最近TA其实更主动了" | 更新信号时间线 |

## 处理流程

### Step 1：识别纠正内容

从用户的话中提取：
- **纠正对象**：哪个 Layer / 维度？
- **纠正内容**：用户说 TA 应该是什么样？
- **纠正力度**：微调 / 修正 / 推翻重来

### Step 2：判断合理性

- 用户有具体场景/证据支撑 → 直接接受纠正
- 用户主观感受但没有具体证据 → 接受但标注 `[用户主观纠正]`
- 用户纠正到与现有数据矛盾 → 询问用户如何判断（已有数据 vs 新纠正）

### Step 3：写入 Correction

#### Profile 纠正格式

在 profile.md 的 `## Correction 记录` 节追加：

```markdown
#### Correction #{序号} — {ISO时间}

**纠正前**：{原来的行为规则/描述}

**纠正后**：{用户说的新行为规则/描述}

**影响 Layer**：{Layer 0/2/3/4/5}

**纠正来源**：{用户口述 / 用户描述具体场景}

**关联规则更新**：
- {调整了哪些相关的行为规则}
```

#### Signal 纠正格式

在 signals.md 的 `## Correction 记录` 节追加：

```markdown
#### Correction #{序号} — {ISO时间}

**纠正维度**：{主动性/回复质量/暧昧信号/邀约信号/温度评估}

**纠正前**：{原评估}

**纠正后**：{新评估}

**影响**：温度从 {X}°C 调整为 {Y}°C
```

### Step 4：立即生效

1. 用 `Edit` 工具修改对应位置的主体内容（不只是 Correction 记录）
2. 确保后续所有输出都使用修正后的规则
3. 重新生成 SKILL.md
4. 更新 meta.json 的 corrections_count

### Step 5：确认

```
✅ 已更新。

{简要说明改了什么}

如果还有不对的地方，继续跟我说。
```

## 特殊处理

### 系统性的推翻

如果用户说"整个都不对"或"重来吧"：

```
好，我们重新来。你觉得最主要的问题是什么？

A. TA的性格判断完全偏了（重做 Profile）
B. TA对这段关系的态度不对（重做 Signal 评估）
C. 都重来（重新创建）
```

### 情感纠正

如果用户纠正的内容带有情感色彩：

```
"TA其实没那么在乎我"
"TA不会拒绝我的"

→ 接受纠正，但不强化用户的自我否定或幻想。
  标注为 [用户主观感受]，提醒这是用户的视角而非客观事实。
```

---

## 纠正原则

1. **用户比数据更了解 TA**：用户的主观感受优先于算法推断
2. **但用户也不一定客观**：标注纠正来源，区分[用户口述]和[用户提供具体场景证据]
3. **即时生效**：不需要重新走分析流程
4. **可追溯**：所有纠正记录在 Correction 层，方便回滚
5. **不争论**：不对用户的纠正说"但数据显示..."，除非纠正与用户自己之前提供的数据严重矛盾
