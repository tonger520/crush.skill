# 增量合并逻辑

## 任务

当用户提供新的聊天记录、社交媒体数据或口述补充时，将增量信息合并到已有的 profile.md 和 signals.md 中，**不覆盖已有结论，而是叠加和更新**。

---

## 合并流程

### Step 1：读取现有数据

```
Read crushes/{slug}/profile.md
Read crushes/{slug}/signals.md
```

### Step 2：分析增量内容

对新提供的内容按以下维度提取增量信息：

#### Profile 增量

对照现有 profile.md 的每个 Layer，检查新内容中是否有：
- Layer 0：新发现的行为模式，或对已有模式的补充/修正
- Layer 1：新的身份信息
- Layer 2：新的口头禅、表达方式变化
- Layer 3：新的互动节奏发现、新的情绪触发条件
- Layer 4：新的关系互动场景
- Layer 5：新的边界或雷区

#### Signal 增量

对照现有 signals.md 的每个维度，检查新内容中是否有：
- 新的主动性信号（新的主动联系、新的话题类型）
- 新的回复质量数据点
- 新的暧昧信号
- 新的邀约信号或拒绝模式

**温度必须重新计算**。

---

### Step 3：合并策略

#### Profile 合并

| 内容类型 | 合并方式 |
|----------|---------|
| **新发现的行为模式** | 追加到对应 Layer，标注 `[新增 — {日期}]` |
| **与已有结论一致** | 在已有结论后追加新证据，标注 `[补充证据 — {日期}]` |
| **与已有结论冲突** | 追加两个版本到对应 Layer，标注冲突，让用户判断 |
| **对已有结论的补充** | 追加到对应位置，标注 `[补充 — {日期}]` |

**冲突处理**：
```
⚠️ 发现冲突：
- 已有结论：{当前 profile 中的内容}
- 新发现：{从新增内容中提取的不同模式}
- 可能原因：{TA 的状态变了 / 数据不足 / 情境差异}
- 建议：{保留两个版本，用更多数据验证}
```

#### Signal 合并

- 加到证据池，重新计算各维度评分
- 更新信号时间线，添加新阶段
- 重新计算暧昧温度

---

### Step 4：冲突上报

如果新内容**系统性修正**了对 TA 的理解（不只一个维度有冲突），主动问用户：

```
新信息和之前的画像有几个地方不太一样，主要是：

1. {冲突点1}
2. {冲突点2}

这可能意味着 TA 的状态在变化，也可能是有不同情境。你想：

A. 保留最新信息为主（TA 变了）
B. 保留原有画像为主（新信息可能是特殊情况）
C. 两个都保留（以后再判断）
```

---

### Step 5：写入更新

1. 对 profile.md 和 signals.md 使用 `Edit` 工具追加增量
2. 追加位置：每个 Layer/维度末尾的 `（更新于 {ISO时间}）` 标记后
3. 重新计算并更新暧昧温度
4. 重新生成 SKILL.md（合并最新文件）
5. 更新 meta.json 的 version 和 updated_at

---

## 合并原则

1. **不覆盖**：新信息追加，不删除已有的合理推断
2. **不强行一致**：人是复杂的，矛盾的数据可能是 TA 本身就矛盾
3. **标注时间**：所有增量都标注时间，以便追踪 TA 行为变化趋势
4. **不过度自信**：数据多了不代表推理更准确，只代表证据更丰富
5. **温度可以回调**：如果新数据显示 TA 降温了，诚实反映，不要找借口
